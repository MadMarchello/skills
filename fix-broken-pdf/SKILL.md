# Починить нечитаемый PDF

PDF на экране нормальный, но копирование и поиск дают мусор (`%B;84FP`, `Ɂ444A<5`) либо текста нет вообще (скан). Создай новый PDF с тем же видом и рабочим текстовым слоем. Скрипт уже написан: `scripts/fix_pdf.py` рядом с этим файлом. Запускай его, не переписывай.

## Жёсткие правила

1. Не изменяй и не перезаписывай исходный PDF. Результат: `<имя> (OCR).pdf` в той же папке.
2. Не ставь пакеты в venv или conda проекта. Только `/tmp/pdfenv`.
3. Не «расшифровывай» мусор заменой символов. Разные буквы часто схлопнуты в один код, это необратимо. Единственный путь — OCR.
4. Служебные файлы и картинки проверки — только в `/tmp`, не в проект.
5. Команда упала с `Operation not permitted` или сетевой ошибкой — повтори ту же команду с `required_permissions: ["all"]`. Другая ошибка дважды подряд — остановись и покажи текст ошибки.
6. PDF с паролем (`encrypted: True`) — остановись и попроси пароль.
7. Не macOS или нет модуля `Vision` — остановись. Скажи, что нужен `ocrmypdf` (`brew install ocrmypdf tesseract-lang`, затем `ocrmypdf --force-ocr -l rus+eng in.pdf out.pdf`). Системные пакеты сам не ставь.

## Подготовка

`SKILL_DIR` — каталог этого скилла (там лежит `SKILL.md`).

```bash
test -x /tmp/pdfenv/bin/python || python3 -m venv /tmp/pdfenv
/tmp/pdfenv/bin/pip install -q -r "$SKILL_DIR/scripts/requirements.txt"
/tmp/pdfenv/bin/python -c "import fitz, Vision; print('OK')"
```

`required_permissions: ["all"]`, `block_until_ms: 300000`. Строка `OK` — успех. Предупреждения pip и `yanked version: pyobjc-core` игнорируй. `ModuleNotFoundError` значит, что вызван не `/tmp/pdfenv/bin/python`.

## Диагностика

```bash
/tmp/pdfenv/bin/python -c "
import sys; sys.path.insert(0, '$SKILL_DIR/scripts')
import fitz, fix_pdf
d = fitz.open('ПУТЬ_К_PDF')
print('pages:', d.page_count, '| encrypted:', d.needs_pass, '| producer:', d.metadata.get('producer'))
for i, p in enumerate(d):
    r, n = fix_pdf.broken_ratio(p)
    print(f'page {i+1}: words={n} broken={r:.0%} | ' + ' '.join(p.get_text().split())[:100])
"
```

| Что видишь | Что делать |
|---|---|
| `broken` > 15% или мусор вида `%B;84FP` | OCR этой страницы |
| `words` < 20, а на странице много текста | OCR (скан) |
| `broken` 0–5%, текст читается | оставить страницу |
| все страницы в порядке | остановись и уточни, что именно нечитаемо |

`--pages auto` выбирает страницы сам. Ручной диапазон (`--pages 2-15,17`) — только если auto явно промахнулся.

## Конвертация

```bash
/tmp/pdfenv/bin/python "$SKILL_DIR/scripts/fix_pdf.py" "ИМЯ.pdf" "ИМЯ (OCR).pdf" --check-dir /tmp/pdf_check
```

`required_permissions: ["all"]`, `block_until_ms: 300000`. Около секунды на страницу.

## Проверка

1. В блоке `=== verification ===` у каждой страницы `broken` ≤ 5% и `words` > 0 там, где есть текст. 1–5% после OCR нормально: регулярка срабатывает на код (`np.array([[1,2]])`) и на единичные ошибки распознавания.
2. Открой 2–3 картинки из `/tmp/pdf_check/` (первую OCR-страницу, самую плотную, последнюю). Красные рамки должны лежать на строках. Съехавшие рамки — ошибка, сообщи о ней.
3. Сверь 2–3 файла `page_XX.txt` с картинками: осмысленный русский или английский, без `\xad` и `\xa0`.
4. Исходный файл не изменился (размер и дата те же), новый появился: `ls -la`.

Если в тексте вместо дефисов и пробелов `\xad` и `\xa0` — шрифт с битой таблицей ToUnicode. Список шрифтов в скрипте не меняй.

## Отчёт

Кратко, по-русски:

1. Полный путь нового файла и что оригинал не тронут.
2. В чём была проблема и на каких страницах.
3. Какие страницы распознаны, какие оставлены.
4. Реальные ошибки OCR, если увидел их при проверке. Код со скриншотов лучше сверять с картинкой.
5. Пакеты ставились в `/tmp/pdfenv`, проектное окружение не трогалось.
