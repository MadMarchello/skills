# Конспект лекции

Конспект — выправленная запись занятия, не учебный пересказ. Слова лектора и студентов не менять по смыслу. Допустима только правка языка и очевидных сбоев распознавания.

## Источники

Найти все три, если есть. Не подменять один другим.

| Источник | Типичные имена | Роль |
|---|---|---|
| Транскрибация | `lecture.txt`, `транскрибация.txt` | Каркас: порядок речи, реплики, таймкоды |
| Презентация | `презентация.pptx` | Заголовки, схемы, формулировки слайдов |
| Исходники | `исходники из лекции*.txt`, ноутбук лекции | Код и SQL, которые показывали |

Если файла нет — сказать, чего не хватает, и собрать из имеющегося. Ноутбук со слайдами не переписывать, пока не попросили.

Текст из `.pptx`: zip + XML слайдов (`ppt/slides/slideN.xml`), пространства имён DrawingML. Слайды с почти пустым текстом (рисунок перцептрона) не дорисовывать — оставить устное описание.

## Процесс

1. **Собрать файлы.** Список каталога лекции; размеры `lecture.txt`; извлечь текст всех слайдов; прочитать исходники целиком.
2. **Кто говорит.** Лектор — по имени, если оно прозвучало (в транскрибации часто «Спикер 2»). Студенты — номерами спикеров. Имена писать только там, где их назвали вслух.
3. **Сверить ход.** Транскрибация задаёт порядок разделов. Номера слайдов в pptx и в файле исходников могут быть сдвинуты — якориться на содержимом, не на цифре. Код вставлять в том месте, где его показывают, дословно из исходников.
4. **Написать конспект.** Markdown рядом с материалами: `lectureN/конспект.md` или путь, который дал пользователь. У разделов — интервал времени из транскрибации.
5. **Чек-лист** в конце этого файла.

Организационный кусок, перерыв и вопросы студентов не выкидывать: это часть записи.

## Правка текста

Можно:

- пунктуация, согласование, орфография;
- склейка фраз, которые ASR разрезал посередине предложения;
- техническое слово, если слайд или код однозначно показывают, что сказали: PyTorch, PostgreSQL, ResNet18, CUDA, `eval`, `backward`.

Нельзя:

- пересказывать «своими словами»;
- выкидывать «ну», «вот», «да» и сглаживать устную речь;
- поправлять содержательные утверждения лектора, даже если они расходятся со слайдом или с обычной терминологией;
- добавлять пояснения, которых на лекции не было;
- угадывать неясное с записи («Чап», обрывки имён, «хэтс»). Оставить как в транскрибации.

Код и подписи со слайдов — отдельным блоком, дословно. Рисунки без текста в pptx не реконструировать.

## Шаблон файла

```markdown
# [Заголовок со слайда 1]

[Курс / модуль / финал лекции — формулировки со слайда, не свои.]

Лектор: [имя, если назвали].

---

## 1. [Тема раздела]

**00:05–00:19**

**Лектор.** [Речь.]

**Студент N.** [Вопрос.]

**Лектор.** [Ответ.]

```python
# код со слайда / из исходников, как показывали
```
```

Дальше — разделы по ходу занятия, не «слайд 1, слайд 2», если речь шла иначе.

## Чек-лист

- [ ] Есть транскрибация, слайды и исходники (или явно сказано, чего нет)
- [ ] Порядок идёт по речи, не по оглавлению презентации в отрыве от записи
- [ ] Реплики студентов на месте, не сжаты в «был вопрос»
- [ ] Код совпадает с файлом исходников
- [ ] Неясный ASR не заменён догадкой
- [ ] Факты лектора не «исправлены»
- [ ] Таймкоды у разделов сверяются с `lecture.txt`
- [ ] Файл конспекта лежит рядом с материалами лекции
